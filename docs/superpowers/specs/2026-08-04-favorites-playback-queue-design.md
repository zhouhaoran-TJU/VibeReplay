# 收藏列表连续播放设计

## 目标

从收藏列表打开视频时，以当前收藏列表的显示顺序建立播放队列，使播放页的“上一个”“下一个”和自动连播功能与目录播放保持一致。

## 行为

- 点击收藏项时，将当时的完整收藏列表作为本次播放会话的队列快照，并定位到被点击的收藏项。
- “上一个”“下一个”、播放完成后的自动切换和列表循环继续遵循现有播放模式。
- 队列顺序与收藏列表显示顺序一致；顺序模式到首尾边界后停止切换，列表循环模式支持首尾循环。
- 队列同时支持普通文件、Shizuku 文件和 `content://` 系统文件。
- 收藏项无法打开时沿用现有失败反馈，并保留队列，允许用户继续切换。

## 实现

扩展现有 `PlaybackItem`，记录 Shizuku 和 content URI 两种来源标记。收藏列表点击事件把收藏快照交给 `openFavoriteItem`，后者转换为统一播放队列后打开选中项；`openPlaybackItem` 根据来源选择正确的 URI 打开方式。目录播放逻辑继续复用同一队列，不新增独立收藏导航状态。

## 测试与发布

- 提取可单元测试的收藏队列转换逻辑，验证顺序、来源类型和选中项定位。
- 运行单元测试并构建 debug、beta APK。
- 版本从 `3.6` / `27` 升级为 `3.7` / `28`，更新发布 APK、哈希、大小和更新说明后推送到现有 `origin/main`。
